# Feature Specification: 求职分析复盘

**Feature Branch**: `003-job-search-analytics`

**Created**: 2026-08-21

**Status**: Complete

**Input**: User description: “新增独立的求职分析模块，按投递周期复盘投递、阶段、Offer 和面经表现。”

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 复盘周期表现 (Priority: P1)

作为个人求职者，我可以按时间范围查看同一批投递的数量、面试率、Offer 率、首次面试等待时间和面经完成率，从而快速了解阶段性结果。

**Why this priority**: 核心指标是分析模块最直接的用户价值。

**Independent Test**: 准备投递日期、阶段和结果已知的记录，选择时间范围后核对全部核心指标与上一周期变化。

**Acceptance Scenarios**:

1. **Given** 用户首次进入分析页，**When** 页面加载，**Then** 系统展示最近 90 天投递 cohort 的五项核心指标。
2. **Given** 入选投递的阶段或结果发生在筛选结束日之后，**When** 系统计算结果，**Then** 后续阶段和当前最终状态仍计入该 cohort。
3. **Given** 用户选择自定义时间，**When** 日期缺失、倒置或晚于当前业务日期，**Then** 系统保留输入、指出错误且不展示错误查询结果。

---

### User Story 2 - 识别趋势和转化 (Priority: P1)

作为个人求职者，我可以查看投递趋势、记录完整的里程碑转化和各阶段到达率，从而发现主要变化与流失环节。

**Why this priority**: 趋势和转化把孤立统计转化为可复盘的求职过程。

**Independent Test**: 使用跨多个周或月且包含重复阶段的样本，核对聚合粒度、独立投递计数和相邻转化率。

**Acceptance Scenarios**:

1. **Given** 时间范围不超过 180 天，**When** 查看趋势，**Then** 系统按周展示投递、获得面试和获得 Offer 的 cohort 数量；更长范围按月展示。
2. **Given** 投递包含重复面试轮次，**When** 查看阶段到达率，**Then** 同一投递在同一阶段只计一次。
3. **Given** Offer 没有对应面试记录，**When** 查看分析，**Then** 总体 Offer 率包含该记录，里程碑转化不包含它，并显示数据完整性提示。

---

### User Story 3 - 比较维度与面试复盘 (Priority: P2)

作为个人求职者，我可以比较不同求职类型和城市的样本表现，并查看面经完成与面试结果，从而完成阶段复盘。

**Why this priority**: 维度和面经分析帮助用户解释整体结果，但依赖足够的数据量。

**Independent Test**: 准备类型、城市、面经状态和面试结果不同的样本，核对排序、分母与小样本提示。

**Acceptance Scenarios**:

1. **Given** 用户按类型或城市筛选，**When** 页面刷新或返回，**Then** URL 和分析结果保留筛选条件。
2. **Given** 面经结果包含待反馈、通过和未通过，**When** 计算通过率，**Then** 待反馈不进入分母。
3. **Given** 当前 cohort 少于 5 条，**When** 查看摘要，**Then** 系统展示原始数据和小样本提示，但不输出维度优劣结论。

### Edge Cases

- 没有投递时显示创建首条投递入口，不渲染空坐标轴。
- 有投递但没有阶段或面经时保留可计算指标，并说明如何补齐记录。
- “全部历史”不提供上一周期比较；今年与上年同期比较，其他有界周期与前一等长周期比较。
- 未填写城市归入“未填写”；城市超过八项时，其余合并为“其他”。
- 所有分析只包含当前用户数据，跨用户记录不得影响计数或维度选项。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为已登录用户提供独立的求职分析入口，并标识当前导航位置。
- **FR-002**: 系统 MUST 支持近 30 天、近 90 天、近 180 天、今年、全部和自定义时间范围，默认近 90 天。
- **FR-003**: 时间筛选 MUST 以投递日期确定 cohort，并将 cohort 后续发生的阶段、面经和当前结果纳入统计。
- **FR-004**: 系统 MUST 支持按求职类型和城市筛选，且筛选状态可通过页面 URL 恢复。
- **FR-005**: 系统 MUST 展示投递数、获得面试率、总体 Offer 率、首次面试等待中位天数和面经完成率。
- **FR-006**: 有界时间段 MUST 展示与对应上一周期的数量或百分点变化；全部历史不得显示无意义比较。
- **FR-007**: 系统 MUST 展示时间趋势、记录完整的里程碑转化和按独立投递计算的阶段到达率。
- **FR-008**: 系统 MUST 提供类型与城市比较，包含样本数、面试率和 Offer 率。
- **FR-009**: 系统 MUST 展示面经数量、完成率、已出结果面经通过率和各面试轮次结果分布。
- **FR-010**: 面经通过率 MUST 排除待反馈记录；Offer 漏斗 MUST 排除缺少前序里程碑的记录。
- **FR-011**: 系统 MUST 使用确定性规则生成复盘摘要，并在样本少于 5 条时停止生成优劣结论。
- **FR-012**: 系统 MUST 明确展示空状态、部分数据状态、验证错误和数据完整性提示。
- **FR-013**: 所有分析和筛选选项 MUST 只使用当前用户的数据。
- **FR-014**: 图表 MUST 同时提供直接数值、文字摘要或数据表，并支持键盘操作和不依赖颜色的辨识方式。
- **FR-015**: 页面 MUST 在 375px、768px 和桌面视口保持可读可操作，且尊重减少动态效果偏好。

### Key Entities

- **分析查询**: 用户选择的周期、起止日期、求职类型和城市。
- **分析报告**: 基于某个投递 cohort 计算的指标、趋势、里程碑、阶段、维度、面经与摘要结果。
- **比较周期**: 当前有界周期之前的等长周期，或今年对应的上年同期。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户能在 30 秒内确认本周期投递规模、面试与 Offer 转化、主要流失阶段和表现最佳的有效样本维度。
- **SC-002**: 使用已知样本验证时，全部指标、筛选、周期比较和分母准确率达到 100%。
- **SC-003**: 每位用户拥有 10,000 条投递及相应面经时，95% 的分析访问在 1 秒内得到结果。
- **SC-004**: 两个用户各自存在分析数据时，跨用户数据混入率为 0%。
- **SC-005**: 分析页通过适用的 WCAG 2.2 AA 自动与人工检查，并满足 LCP p75 ≤ 2.5 秒、INP p75 ≤ 200 毫秒、CLS ≤ 0.1。

## Assumptions

- 业务日期继续按 `Asia/Shanghai` 解释。
- 转化反映查看时的最新投递状态，不冻结历史快照。
- 首版不提供行业基准、目标管理、导出、AI 或面经正文语义分析。
- 现有首页概览保持不变，新分析页为只读能力。
