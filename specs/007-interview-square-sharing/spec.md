# Feature Specification: 个人面经与面经广场

**Feature Branch**: `codex/007-interview-square-sharing`

**Created**: 2026-09-13

**Status**: Ready

**Input**: User description: “将面经放到头像下拉框并改为个人面经；当前面经模块改为面经广场；用户可以选择公开或私有面经，公开面经可在广场查看，私有面经只有本人可查看。广场仅登录可见，公开时可匿名或署名，且只公开脱敏内容。”

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 安全发布已完成面经 (Priority: P1)

作为面经作者，我可以把已完成的面经以匿名或署名方式发布到面经广场，也可以随时下架，从而在主动选择的前提下分享经验。

**Why this priority**: 没有清晰、可逆且默认私有的发布机制，就无法安全地建立面经广场。

**Independent Test**: 创建并完成一篇面经，分别验证匿名发布、署名发布、切换署名方式、下架和降级复盘状态，确认每一步的公开状态与展示身份正确。

**Acceptance Scenarios**:

1. **Given** 用户新建或拥有历史面经，**When** 查看分享设置，**Then** 面经默认为私有，且没有公开副本。
2. **Given** 面经仍为草稿或待复盘，**When** 用户尝试公开，**Then** 系统阻止发布并提示必须先完成复盘。
3. **Given** 面经已完成，**When** 用户选择匿名公开并确认，**Then** 面经进入广场且不展示任何作者身份。
4. **Given** 面经已完成，**When** 用户选择署名公开并确认，**Then** 广场只展示作者头像和用户名。
5. **Given** 面经已经公开，**When** 作者切换匿名或署名方式，**Then** 广场身份展示随保存结果更新，面经内容不产生副本。
6. **Given** 面经已经公开，**When** 作者改为私有或把复盘状态改为未完成，**Then** 面经立即从广场下架，系统明确告知下架结果。

---

### User Story 2 - 浏览面经广场 (Priority: P1)

作为已登录的求职者，我可以在面经广场浏览并按公司搜索其他用户公开的面经，同时直接阅读脱敏内容，从而参考真实面试经验而不接触作者的私人求职数据。

**Why this priority**: 广场的核心价值是让公开面经可以被发现和阅读，同时严格限制公开数据范围。

**Independent Test**: 准备匿名公开、署名公开、私有和已下架面经，使用不同用户浏览列表和详情，确认只有公开且已完成的记录出现，并且返回字段完全符合公开范围。

**Acceptance Scenarios**:

1. **Given** 用户已登录且存在公开面经，**When** 打开“面经广场”，**Then** 系统以单列社交动态流按最近发布时间优先展示公开且已完成的面经，并在动态卡片中直接呈现脱敏正文，无需先进入表格或详情页。
2. **Given** 广场包含多家公司的面经，**When** 用户输入公司名称搜索，**Then** 只展示公司名称部分匹配的公开面经，并保留搜索词。
3. **Given** 用户打开匿名面经，**When** 查看列表或详情，**Then** 页面显示“匿名用户”，响应中不包含可追溯作者的信息。
4. **Given** 用户打开署名面经，**When** 查看列表或详情，**Then** 页面只显示作者头像和用户名，不提供邮箱、个人中心链接或其他资料。
5. **Given** 用户知道私有、未完成或已下架面经的标识，**When** 尝试访问公开详情，**Then** 系统以“未找到”响应处理且不泄露其存在性。
6. **Given** 未登录访客，**When** 访问广场列表或详情，**Then** 页面要求登录，接口拒绝返回面经内容。

---

### User Story 3 - 从账号菜单管理个人面经 (Priority: P2)

作为面经作者，我可以从头像下拉菜单进入“个人面经”，查看和筛选自己的全部面经及其分享状态；主导航中的原“面经”入口则明确指向“面经广场”。

**Why this priority**: 将个人内容与社区浏览分层，可以避免用户误以为私人草稿会出现在公共广场。

**Independent Test**: 从任意受保护页面打开头像菜单进入个人面经，再从主导航进入广场，确认两者的标题、内容范围、当前状态和返回路径清晰区分。

**Acceptance Scenarios**:

1. **Given** 用户位于任意已登录页面，**When** 打开头像菜单，**Then** 菜单在个人中心附近提供“个人面经”入口。
2. **Given** 用户点击主导航“面经广场”，**When** 页面加载，**Then** 页面仅展示公开面经，不展示用户的私有列表。
3. **Given** 用户进入“个人面经”，**When** 查看列表，**Then** 系统展示自己的全部面经，并以文字和非颜色唯一方式区分私有、匿名公开和署名公开。
4. **Given** 用户拥有多种分享状态的面经，**When** 按分享状态筛选，**Then** 列表只展示符合条件的本人面经，并提供清除条件入口。
5. **Given** 用户从投递详情或个人面经列表打开面经，**When** 编辑或返回，**Then** 系统保持所有者编辑路径，不跳入只读的广场详情。

### Edge Cases

- 多个页面同时编辑同一面经时，发布设置与正文继续使用版本冲突保护，旧版本不得覆盖新版本。
- 一次更新同时把已完成面经改为未完成和公开时，最终结果必须为私有，不允许产生瞬时公开状态。
- 发布保存失败时，界面保留用户选择并提示重试；不得在无法确认写入成功时显示“已公开”。
- 作者删除公开面经或删除其关联投递后，广场列表和详情不再可访问该内容。
- 作者账号被删除时，现有级联删除规则继续生效，不保留署名或匿名孤立副本。
- 匿名面经不得通过排序、筛选、错误信息、响应字段或图片地址之外的隐含字段泄露作者身份；头像在匿名模式下不请求。
- 署名作者缺少头像时使用现有文字头像降级方案；不得因此暴露邮箱。
- 广场没有内容、公司搜索无结果、加载失败和详情已下架时均提供可继续操作的明确反馈。
- 长公司名、岗位名和用户内容在窄视口换行，不产生横向滚动；所有搜索、菜单和分享控件均可使用键盘操作。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 将所有历史和新建面经的默认分享状态设为私有。
- **FR-002**: 系统 MUST 只允许“已完成”的面经公开；草稿和待复盘面经不得进入广场。
- **FR-003**: 作者 MUST 能够将已完成面经选择为匿名公开或署名公开，并能够在两种模式间切换。
- **FR-004**: 匿名 MUST 是用户首次选择公开时的默认作者展示方式。
- **FR-005**: 作者 MUST 能够随时把公开面经改为私有；公开面经变为草稿或待复盘时系统 MUST 自动下架并提示。
- **FR-006**: 发布、署名方式切换和下架 MUST 与现有面经版本校验一起原子保存，不得创建公开内容副本。
- **FR-007**: 系统 MUST 记录当前公开面经的发布时间；下架时清除发布时间，重新发布时记录新的发布时间。
- **FR-008**: 系统 MUST 提供仅已登录用户可访问的面经广场，并默认按发布时间从近到远展示。
- **FR-009**: 广场 MUST 只返回同时满足“公开”和“已完成”的面经。
- **FR-010**: 广场 MUST 仅提供公司名称搜索，支持不区分大小写的部分匹配；不得在广场首屏呈现岗位、正文、轮次或日期筛选控件。
- **FR-011**: 广场 MUST 使用游标分页，搜索翻页时保持当前公司条件并防止私有记录影响结果总数或游标。
- **FR-012**: 公开面经 MUST 只展示面经标识、公司、岗位、轮次、面试日期、公开问题分类与回答文本、亮点、不足和发布时间。
- **FR-012A**: 广场 MUST 使用单列社交动态卡片而非表格或摘要行，并在每张卡片中直接展示作者标识、发布时间、公司岗位、轮次、面试日期及完整脱敏面经正文；独立详情入口作为辅助阅读路径保留。
- **FR-012B**: 广场首页 MUST 采用紧凑的内容优先布局，不显示独立的大型“面经广场”页面标题区；“最新面经”作为内容流标题，“我的面经”作为次要入口。
- **FR-013**: 公开响应 MUST 排除所有者标识、投递标识、阶段发生标识、内部版本、面试官备注、行动项、个人评分、投递结果和其他账号信息。
- **FR-014**: 匿名公开时系统 MUST 不返回作者对象；界面 MUST 使用不可追溯的“匿名用户”标签。
- **FR-015**: 署名公开时系统 MUST 只返回头像和用户名；不得返回邮箱、显示名、角色、个人中心链接或其他资料。
- **FR-016**: 私有、未完成、已下架或不存在的面经通过广场详情访问时 MUST 使用相同的未找到结果。
- **FR-017**: 所有面经写操作 MUST 继续要求有效登录会话并校验所有者；管理员不得仅凭角色读取他人私有面经。
- **FR-018**: 主导航 MUST 将“面经”改为“面经广场”并指向广场首页。
- **FR-019**: 头像下拉菜单 MUST 新增“个人面经”入口并指向独立的个人列表。
- **FR-020**: 个人面经列表 MUST 展示作者自己的全部面经，并支持按私有、匿名公开和署名公开筛选。
- **FR-021**: 个人面经列表、投递详情和分析模块中的所有者数据范围 MUST 不受分享状态影响。
- **FR-022**: 面经新建与所有者编辑深链 MUST 保持兼容；广场详情 MUST 使用独立的只读路径。
- **FR-023**: 分享设置 MUST 明确列出公开范围，并为保存中、成功、失败、自动下架和版本冲突提供可识别反馈。
- **FR-024**: 页面 MUST 支持键盘操作、可见焦点、语义化标题、可识别的选中状态和状态反馈，并满足适用的 WCAG 2.2 AA 标准。
- **FR-025**: 广场和个人面经 MUST 在桌面与 375 像素宽视口可用，长文本可换行且无页面级横向溢出。
- **FR-026**: 在每用户最多 10,000 篇面经的代表性数据下，广场读取 MUST 达到 500 毫秒 p95 以内，发布更新 MUST 达到 1 秒 p95 以内。
- **FR-027**: 页面 MUST 满足项目宪章规定的 LCP p75 ≤ 2.5 秒、INP p75 ≤ 200 毫秒和 CLS ≤ 0.1。

### Key Entities

- **面经分享设置（Interview Publication）**: 面经上的分享状态、作者展示方式和当前发布时间；与原面经同一生命周期，不形成内容副本。
- **公开面经摘要（Public Interview Summary）**: 广场列表使用的最小脱敏数据，只包含发现和辨识面经所需字段。
- **公开面经详情（Public Interview Detail）**: 登录用户可阅读的脱敏内容视图，不包含任何所有者私有字段。
- **公开作者（Public Author）**: 仅在署名模式存在，只包含用户名和头像；匿名模式下不存在该实体。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 至少 90% 的首次使用者能在 30 秒内正确识别私有状态，并完成一次匿名或署名发布。
- **SC-002**: 历史和新建面经在用户主动发布前的公开率为 0%，私有内容跨用户泄露率为 0%。
- **SC-003**: 匿名面经响应中的可追溯作者字段数量为 0；署名响应除头像和用户名外的账号字段数量为 0。
- **SC-004**: 作者发布、切换署名方式、下架或降级复盘状态后，广场在下一次读取时呈现正确状态的准确率为 100%。
- **SC-005**: 在 1,000 篇公开面经的代表性数据中，用户可以在 10 秒内通过公司搜索定位目标面经，95% 的读取操作在 500 毫秒内完成。
- **SC-006**: 100% 的测试参与者能够区分主导航“面经广场”和头像菜单“个人面经”的内容范围。
- **SC-007**: 用户可仅使用键盘完成广场公司搜索、详情阅读、个人列表筛选和分享设置，适用界面通过 WCAG 2.2 AA 检查。
- **SC-008**: 广场与个人面经页面在支持视口下满足 LCP p75 ≤ 2.5 秒、INP p75 ≤ 200 毫秒和 CLS ≤ 0.1。
- **SC-009**: 用户打开广场后，无需额外进入详情页即可阅读当前页 100% 的公开面经正文，并能在 5 秒内识别作者模式、公司岗位、轮次和发布时间。

## Assumptions

- 本规格是 `002-interview-review` 的增量；仅替代其 FR-023/FR-024 中“所有读取仅限本人、首期不公开”的部分，原有所有者写权限和其他行为继续有效。
- 第一版不提供点赞、评论、收藏、关注、举报、内容审核或公开个人主页。
- 广场仅向已登录用户开放，沿用现有认证与受保护布局。
- 公开范围基于当前结构化面经字段，不新增公开 Markdown 副本。
- 动态流首版不加入点赞、评论或转发；“朋友圈式”仅指按发布时间排列、以作者与正文为中心的单列内容卡片。
- 个人导出继续导出所有者数据，不因公开状态改变内容范围。
- 删除面经、投递或账号继续使用现有级联规则，不保留孤立公开副本。
