# Domain Docs

工程技能在探索代码库时应如何消费本仓库的领域文档。

## 探索前先读

- 仓库根目录的 `CONTEXT.md`
- `docs/adr/`：阅读与当前工作区域相关的 ADR

这些文件不存在时**静默继续**：不要标记缺失，也不要主动建议创建。`/domain-modeling` 技能会在术语或决策真正落定时惰性创建它们。

## 文件结构（单上下文）

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── 0002-xxx.md
└── src/
```

## 使用词汇表的术语

输出（issue 标题、重构提案、假设、测试名）中命名领域概念时，使用 `CONTEXT.md` 定义的术语，不要漂移到词汇表明确回避的同义词。

需要的概念不在词汇表里是个信号：要么你在发明项目不用的语言（重新考虑），要么存在真实缺口（记下来给 `/domain-modeling`）。

## 标记 ADR 冲突

输出与现有 ADR 矛盾时显式提出，而不是静默覆盖：

> _与 ADR-0007（xxx）矛盾，但值得重开，因为……_
