# 数据导入与导出

JobTrace 支持用 CSV/XLSX 批量创建投递记录、导出投递表格，以及把面经导出为 Markdown。所有操作都要求登录，并只读取或写入当前用户的数据。

## 投递导入

### 文件限制

- 支持 `.csv` 和 `.xlsx`。
- 文件最大 5 MB，数据最多 10,000 行。
- CSV 必须使用 UTF-8，不支持含 NUL 字节的二进制内容。
- XLSX 只读取第一个工作表。
- 第一行必须是列名，数据行号从第 2 行开始。

### 字段

| 字段     | 接受的列名                         | 必填 | 格式与限制                           |
| -------- | ---------------------------------- | ---- | ------------------------------------ |
| 公司     | `companyName`、`公司`、`公司名称`  | 是   | 去除首尾空白后 1–200 字符。          |
| 岗位     | `positionName`、`岗位`、`岗位名称` | 是   | 去除首尾空白后 1–200 字符。          |
| 投递日期 | `appliedDate`、`投递日期`          | 是   | ISO 日期 `YYYY-MM-DD`。              |
| 类型     | `type`、`类型`                     | 否   | 见下方值表；空缺时默认为“秋招”。     |
| 城市     | `city`、`城市`                     | 否   | 最多 100 字符。                      |
| 职位链接 | `jobUrl`、`职位链接`               | 否   | 空值或最长 2048 字符的 HTTP(S) URL。 |
| 备注     | `notes`、`备注`                    | 否   | 最多 10,000 字符。                   |
| 状态     | `status`、`状态`、`投递`           | 否   | 见下方值表；空缺时默认为“已投递”。   |

类型可使用中文标签或稳定代码：

| 中文       | 代码                       |
| ---------- | -------------------------- |
| 暑期实习   | `summer_internship`        |
| 日常实习   | `daily_internship`         |
| 秋招提前批 | `early_campus_recruitment` |
| 秋招       | `campus_recruitment`       |
| 社招       | `social_recruitment`       |

状态可使用：

| 中文   | 代码        |
| ------ | ----------- |
| 已投递 | `submitted` |
| Offer  | `offer`     |
| 拒绝   | `refused`   |

> [!NOTE]
> 当前表格导入只创建投递基础信息，不导入招聘阶段、历史事件或面经。创建成功时系统仍会生成正常的投递创建事件。

### 示例

```csv
公司,岗位,投递日期,类型,城市,职位链接,状态,备注
示例科技,前端工程师,2026-08-24,秋招,上海,https://example.test/jobs/1,已投递,官网投递
示例数据,数据分析师,2026-08-20,campus_recruitment,北京,,offer,已收到意向
```

### 预检与确认

上传不会立即写入投递表：

1. 服务端规范化列名和值，并逐行显示校验问题。
2. 系统通过一次集合查询，按当前用户范围内的“公司名称 + 岗位名称 + 投递日期”识别重复候选。
3. 有效行默认选择“创建新记录”，无效行只能跳过；重复候选不会覆盖原记录，是否继续创建由用户决定。
4. 确认请求由一个数据库事务处理全部选择，并逐行隔离业务失败，最终显示已创建、已跳过和失败数量。

预检批次 24 小时后过期，且只能确认一次。确认过程中单行失败不会撤销之前已经创建的其他行，因此重复提交前应先检查结果和投递列表。

> [!WARNING]
> 导入不是更新或合并工具。重复候选选择“创建新记录”会产生新的独立投递。

## 投递导出

投递列表支持三种范围：

- 全部记录；
- 当前筛选结果；
- 当前选中的记录（一次最多 100 条）。

格式为 CSV 或 XLSX，列顺序是：公司、岗位、城市、职位链接、投递日期、类型、状态、备注。中文标签会写入类型和状态列；职位链接在 XLSX 中为安全的 HTTP(S) 超链接。

为降低表格公式注入风险，以 `=`、`+`、`-`、`@`、制表符或回车开头的文本会加单引号。CSV 响应包含 UTF-8 BOM，便于常见中文表格软件直接打开。

导出只包含投递当前快照，不包含阶段时间线、事件历史、面经、账号或管理审计。

## 面经导出

面经列表可一次选择最多 100 篇：

- 单篇导出为 UTF-8 Markdown 文件。
- 多篇导出为 ZIP，每篇面经一个 Markdown 文件。

文件名由公司、岗位、阶段和时长组成；不安全的文件名字符会被替换，重名文件自动加序号。导出内容由当前面经聚合生成，响应使用 `private, no-store`，不会缓存到共享代理。

## 隐私与恢复边界

- 导入批次、逐行错误和确认结果保存在 PostgreSQL，并按当前用户隔离。
- 导出接口会重新校验登录用户和所选 ID，不信任浏览器提供的数据归属。
- 下载文件可能包含职位链接、备注和完整面经；应按个人敏感数据保存，不要上传到公开位置。
- 投递导出适合迁移当前投递快照，但完整灾难恢复必须使用 PostgreSQL 备份。备份流程见[运行与运维](operations.md#备份与恢复)。
